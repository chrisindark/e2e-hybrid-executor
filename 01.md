### 1.2 Boundary Isolation Rules (not yet enforced)

Nothing below is checked by CI or lint today — `services/*` are empty, so these
are conventions to hold to as the services are built.

1. **Zero Direct Import Rule:** `services/runner-e2e`, `services/runner-api`, and
   `services/ai-service` must NEVER directly import each other. All inter-service
   data exchanges must conform strictly to `packages/contracts`.
2. **Worker Purity:** Workers (`runner-e2e`, `runner-api`) never serve external
   HTTP traffic. They consume jobs exclusively from Redis queues and report
   status events via Redis Streams.
3. **Database Access Restriction:** Only `apps/gateway-api` and `packages/db`
   execute DDL migrations. Microservices access the database strictly through
   tenant-scoped repositories or RPC/events.

## 2. PostgreSQL Multi-Tenancy & Row-Level Security (RLS)

Every tenant's data resides in a single, shared PostgreSQL database. Isolation is enforced at the database engine level via PostgreSQL Row-Level Security (RLS) policies. Application code never relies on manual `WHERE tenant_id = :tenantId` filtering for security.

### 2.1 PostgreSQL Kernel Isolation Architecture

```
                      Client Request (Bearer JWT)
                                  │
                                  ▼
                     ┌───────────────────────────┐
                     │ apps/gateway-api          │
                     │ TenantContextMiddleware   │
                     │ Sets: tenantId in ALS     │
                     └─────────────┬─────────────┘
                                   │
                                   ▼
                     ┌───────────────────────────┐
                     │ packages/db               │
                     │ Transactional Runner      │
                     │ BEGIN;                    │
                     │ SET LOCAL app.tenant_id..;│
                     └─────────────┬─────────────┘
                                   │
                                   ▼
             ┌───────────────────────────────────────────┐
             │ PostgreSQL 16 Engine                      │
             │ Current Setting: app.tenant_id = 'org_123'│
             │                                           │
             │  ┌──────────────────────────────────────┐ │
             │  │ Row-Level Security (RLS) Filter      │ │
             │  │ tenant_id = current_setting(...)     │ │
             │  └──────────────────────────────────────┘ │
             │                                           │
             │ [Tenant A Rows]     [Tenant B Rows (BLOCKED)]
             └───────────────────────────────────────────┘
```

```sql
-- Enable UUID generation
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- ============================================================================
-- 1. TENANTS & MEMBERSHIP
-- ============================================================================
CREATE TABLE tenants (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    slug VARCHAR(64) UNIQUE NOT NULL,
    name VARCHAR(255) NOT NULL,
    plan_tier VARCHAR(32) NOT NULL DEFAULT 'free', -- 'free', 'starter', 'pro', 'enterprise'
    max_concurrent_runs INT NOT NULL DEFAULT 2,
    monthly_run_quota INT NOT NULL DEFAULT 500,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- ============================================================================
-- 2. IMMUTABLE TEST SPECIFICATIONS & VERSIONS
-- ============================================================================
CREATE TABLE tests (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    execution_mode VARCHAR(32) NOT NULL DEFAULT 'hybrid', -- 'deterministic', 'hybrid', 'agentic'
    target_url TEXT NOT NULL,
    created_by UUID NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE test_versions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    test_id UUID NOT NULL REFERENCES tests(id) ON DELETE CASCADE,
    version_number INT NOT NULL,
    spec JSONB NOT NULL, -- Canonical TestSpec v1 JSON representation
    commit_message TEXT,
    created_by UUID NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_test_version UNIQUE (tenant_id, test_id, version_number)
);

-- Point active version back to test
ALTER TABLE tests ADD COLUMN active_version_id UUID REFERENCES test_versions(id);

-- ============================================================================
-- 3. TEST RUNS & ATTEMPTS
-- ============================================================================
CREATE TABLE test_runs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    test_id UUID NOT NULL REFERENCES tests(id) ON DELETE CASCADE,
    version_id UUID NOT NULL REFERENCES test_versions(id) ON DELETE RESTRICT,
    status VARCHAR(32) NOT NULL DEFAULT 'queued',
    -- 'queued', 'leased', 'running', 'passed', 'failed', 'recovered', 'errored', 'timed_out', 'cancelled'
    runner_type VARCHAR(16) NOT NULL DEFAULT 'e2e', -- 'e2e' (Playwright), 'api' (HTTP-only)
    idempotency_key VARCHAR(128),
    triggered_by VARCHAR(32) NOT NULL DEFAULT 'manual', -- 'manual', 'ci', 'schedule'
    trigger_identity JSONB,
    variables_override JSONB DEFAULT '{}'::jsonb,
    started_at TIMESTAMPTZ,
    finished_at TIMESTAMPTZ,
    duration_ms INT,
    error_summary TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_tenant_idempotency UNIQUE (tenant_id, idempotency_key)
);

CREATE TABLE run_attempts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    run_id UUID NOT NULL REFERENCES test_runs(id) ON DELETE CASCADE,
    attempt_number INT NOT NULL,
    worker_id VARCHAR(128) NOT NULL,
    status VARCHAR(32) NOT NULL,
    failure_classification VARCHAR(64), -- 'infra_oom', 'infra_timeout', 'browser_crash', 'assertion_failure', 'locator_drift'
    raw_error TEXT,
    started_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    finished_at TIMESTAMPTZ,
    CONSTRAINT uq_run_attempt UNIQUE (run_id, attempt_number)
);

CREATE TABLE run_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    run_id UUID NOT NULL REFERENCES test_runs(id) ON DELETE CASCADE,
    attempt_number INT NOT NULL,
    step_order INT NOT NULL,
    step_id VARCHAR(64) NOT NULL,
    event_type VARCHAR(64) NOT NULL, -- 'step.started', 'step.passed', 'step.drifted', 'step.healed', 'step.failed'
    payload JSONB NOT NULL DEFAULT '{}'::jsonb,
    timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_run_step_event UNIQUE (tenant_id, run_id, attempt_number, step_order, event_type)
);

-- ============================================================================
-- 4. PROMOTION CANDIDATES (SELF-HEALING)
-- ============================================================================
CREATE TABLE promotion_candidates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    test_id UUID NOT NULL REFERENCES tests(id) ON DELETE CASCADE,
    version_id UUID NOT NULL REFERENCES test_versions(id) ON DELETE CASCADE,
    run_id UUID NOT NULL REFERENCES test_runs(id) ON DELETE CASCADE,
    step_id VARCHAR(64) NOT NULL,
    original_locator JSONB NOT NULL,
    proposed_locator JSONB NOT NULL,
    reasoning TEXT NOT NULL,
    dom_snapshot_hash VARCHAR(64),
    status VARCHAR(32) NOT NULL DEFAULT 'pending', -- 'pending', 'approved', 'rejected'
    decided_by UUID,
    decided_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

-- ============================================================================
-- 5. ROW-LEVEL SECURITY ENFORCEMENT
-- ============================================================================

-- Function to safely extract session tenant UUID
CREATE OR REPLACE FUNCTION current_tenant_id() RETURNS UUID AS $$
BEGIN
    RETURN NULLIF(current_setting('app.tenant_id', true), '')::UUID;
END;
$$ LANGUAGE plpgsql STABLE;

-- Enable RLS on all tenant-isolated tables
ALTER TABLE tests ENABLE ROW LEVEL SECURITY;
ALTER TABLE test_versions ENABLE ROW LEVEL SECURITY;
ALTER TABLE test_runs ENABLE ROW LEVEL SECURITY;
ALTER TABLE run_attempts ENABLE ROW LEVEL SECURITY;
ALTER TABLE run_events ENABLE ROW LEVEL SECURITY;
ALTER TABLE promotion_candidates ENABLE ROW LEVEL SECURITY;

-- Create Tenant Policies
CREATE POLICY tenant_isolation_tests ON tests
    FOR ALL
    USING (tenant_id = current_tenant_id())
    WITH CHECK (tenant_id = current_tenant_id());

CREATE POLICY tenant_isolation_test_versions ON test_versions
    FOR ALL
    USING (tenant_id = current_tenant_id())
    WITH CHECK (tenant_id = current_tenant_id());

CREATE POLICY tenant_isolation_test_runs ON test_runs
    FOR ALL
    USING (tenant_id = current_tenant_id())
    WITH CHECK (tenant_id = current_tenant_id());

CREATE POLICY tenant_isolation_run_attempts ON run_attempts
    FOR ALL
    USING (tenant_id = current_tenant_id())
    WITH CHECK (tenant_id = current_tenant_id());

CREATE POLICY tenant_isolation_run_events ON run_events
    FOR ALL
    USING (tenant_id = current_tenant_id())
    WITH CHECK (tenant_id = current_tenant_id());

CREATE POLICY tenant_isolation_promotion_candidates ON promotion_candidates
    FOR ALL
    USING (tenant_id = current_tenant_id())
    WITH CHECK (tenant_id = current_tenant_id());

-- Indexes for performance
CREATE INDEX idx_tests_tenant_id ON tests(tenant_id);
CREATE INDEX idx_test_versions_test ON test_versions(tenant_id, test_id);
CREATE INDEX idx_test_runs_tenant_status ON test_runs(tenant_id, status);
CREATE INDEX idx_run_events_run_attempt ON run_events(tenant_id, run_id, attempt_number);
```

> not match them, so the live schema
> (`packages/db/migrations/1792039710322-initial_schema.ts` and
> `apps/gateway-api/src/shared/*.entity.ts`) was mapped onto it first:

| RFC table              | Live table                           |
| ---------------------- | ------------------------------------ |
| `tenants`              | `tenants` (created by the migration) |
| `tests`                | `test_definitions`                   |
| `test_versions`        | `test_versions`                      |
| `test_runs`            | `runs`                               |
| `run_attempts`         | `step_attempts`                      |
| `run_events`           | `trace_events`                       |
| `promotion_candidates` | `promotion_candidates`               |

The columns are camelCase (`"tenantId"`), not the RFC's `tenant_id`, and
`test_steps` — which the DDL above misses entirely — is isolated too. Two
migrations implement this, both **applied**:

- `packages/db/migrations/1792066610064-tenant-isolation-rls.ts` — creates
  `tenants`, adds `tenantId` to the seven isolated tables (FKs + indexes), adds
  `current_tenant_id()`, and enables **and forces** RLS with one
  `tenant_isolation_<table>` policy per table.
- `packages/db/migrations/1792069042212-tenant-roles-and-defaults.ts` — the part
  that makes RLS bite. `FORCE ROW LEVEL SECURITY` does not constrain a superuser,
  and the docker `POSTGRES_USER` (`orchestrator`) is one, so the app must not
  connect as it. This migration creates the runtime roles and sets
  `DEFAULT current_tenant_id()` on every isolated `tenantId` column, so the tenant
  is stamped by the database rather than trusted from the request payload.

## 3. Migration & Verification Strategy

### 3.1 Steps 3-4: applied, with one deviation

Workspace initialization and local Postgres/Redis (steps 1 and 2 of the original
plan) are done.

**Step 3 — Database Migration: done.** Both migrations in §2.2 are applied via
`pnpm --filter @repo/db run db:migrate`, and RLS is verified (see §3.2).

**Step 4 — Repository Decoupling: done, but not the way this document first
described.** The plan was to re-point `apps/gateway-api` at `TenantDatabaseClient`,
the raw-`pg` helper in `packages/db`. But the gateway reaches the database only
through TypeORM repositories, so that would have meant rewriting every service as
raw SQL. Instead the gateway keeps TypeORM and gains a per-request tenant
connection:

- `TenantScopeInterceptor` (global `APP_INTERCEPTOR`) checks out one connection per
  authenticated request, runs `set_config('app.tenant_id', …, false)` on it, and
  publishes the bound `EntityManager` through an `AsyncLocalStorage`
  (`database/tenant-context.ts`).
- `database/tenant-repository.ts` wraps each `@InjectRepository(...)` provider so
  calls resolve against that request's manager. The four tenant-touching services
  are unchanged; the providers moved into a global `TenantRepositoriesModule`,
  which replaces `TypeOrmModule.forFeature`.

Two deliberate deviations from the RFC wording:

1. The setting is **session-scoped on an exclusive connection**, not `SET LOCAL`.
   Services own their own transactions, and the queued run is fire-and-forget and
   outlives the request; `runWithTenant` gives that background run its own scoped
   connection.
2. Tenant identity is never taken from the payload. The `tenantId` columns are
   `insert: false, update: false` in the entities, so the app cannot write them and
   the database default fills them.
3. The GUC name is shared rather than re-typed per client. `@repo/db` exports
   `TENANT_SETTING` and the gateway's `TenantTransactionService` imports it, so the
   TypeORM client and the worker-side `TenantDatabaseClient` cannot drift apart.
   Migrations keep the literal on purpose: an applied migration is a historical
   record, not a consumer of a source constant.

Runtime traffic connects as `app_runtime` (`DATABASE_APP_URL`); migrations keep
using the owning role (`DATABASE_URL`). `PostgresService` warns at boot if the
runtime connection is a superuser, which is the failure mode that makes RLS inert.

**Still outstanding:** the workers (`services/*`) do not exist yet, so the
`TenantDatabaseClient` path is unexercised. `apps/gateway-api` now depends on
`@repo/db` for the shared `TENANT_SETTING` name, but still reaches the database
through TypeORM rather than through that client.
